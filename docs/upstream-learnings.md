## Principles worth retaining

1. **Local retrieval remains useful without a model.** Cavemem falls back to keyword search if no matching embeddings or usable provider are available. Iron can make deterministic lexical retrieval the initial product, avoiding model startup, network calls, and a worker dependency.
2. **Compact search, explicit expansion.** Cavemem's MCP search returns IDs and snippets, with a separate full-body fetch. Iron should retain that separation and add a hard final serialized UTF-8 byte limit. A result-count cap is not a byte cap, especially for non-ASCII text and provenance fields.
3. **Privacy belongs at every write boundary.** Cavemem's current summary redaction addresses the fact that assistant text can repeat credentials. Iron's derived index must inspect all imported prose and user-controlled metadata rather than assuming a compressed source is already safe. The pinned raw import deliberately bypasses `MemoryStore` to preserve bytes, so it must not be treated as a privacy sanitizer.
4. **Source bytes and source meaning are different contracts.** Cavemem preserves technical tokens during compression and avoids recompressing imported observations. Iron should retain compression flags, intensity, session IDs, timestamps, and source IDs. It should not claim that expanding abbreviated prose reconstructs omitted nuance or verifies a historical statement.
5. **Missing lifecycle events must not break storage.** Cavemem creates a minimal session before child writes and makes session start idempotent. Iron's read-only migration should tolerate valid legacy provenance while surfacing malformed rows, without inventing semantic facts or silently dropping record classes.
6. **Errors must reach the actual caller.** Upstream hook results, CLI failures, and protocol tests treat failure reporting as part of the interface. Iron must test CLI and native stdio MCP boundaries, not only internal Rust functions.

The inspected hybrid ranking loads every stored embedding for a matching model and computes cosine scores in process. That is an explicit scaling cost, not evidence that embeddings are categorically unnecessary. Likewise, quoting whitespace-separated terms avoids raw FTS syntax, but the resulting conjunction can be restrictive for natural questions. Only calibration-set evidence should inform ranking changes; held-out wording must stay fixed.

## Improvements to require in Iron's own verification

- Import a complete source group atomically. Only a successful complete scan may retire records that disappeared. An unreadable directory, oversized file, broken symlink policy, or SQL read error must not become a successful empty snapshot. This follows both the upstream transaction lesson and the shared harness's documented absent-versus-unknown sync failure.
- Separate stable event identity from content-addressed storage. Two distinct sources may share content while retaining separate attribution. Canonical paths should collapse aliases of the same file; aliases must not multiply historical events.
- Check current data, not just successful command exits: summary totals, unchanged replay counters, changed/deleted file behavior, source fingerprints, and provenance metadata. Preserve the existing Cavemem capture path during validation.
- Check privacy in full retrieval, compact snippets, metadata, error output, and JSON serialization. Test Unicode, unclosed private spans, credential-shaped fixtures, and source paths as untrusted data.
- Exercise exact project keys, globals, strict isolation, worktree/root resolution, and explicit overrides. A memory record is evidence, never approval for deployment or a current verification verdict.
- Exercise import failures before and during refresh, unsupported schemas, missing explicit sources, and source removal without partial-prune data loss.
- Exercise output budgets on the final stdout bytes, including JSON escaping, Unicode encoding, envelopes, and the final newline. No-match and truncation must remain valid, explicit JSON.
- Preserve access to competing or dated evidence. Retrieval can surface contradictory records; it must not fabricate a resolution or silently promote an obsolete note into current policy.

These are verification targets. This document does not assert that the Iron implementation satisfies them.

## Tests and measurement lessons

The pinned source contains import tests for byte-preserving round trips, replay, cross-database ID collisions, malformed-file rollback, and dry-run; hook tests cover working-directory scoping, lifecycle replays, missing session start, realistic tool field names, and a warm hook-time bound. Memory search tests cover model absence and wrong embedding dimensions. Privacy tests exercise stored observation and summary bytes as well as the scrubber itself. The package also documents installed-package end-to-end checks because bundling, native adapter loading, and entrypoint detection can fail despite unit tests. These files were inspected, not executed in this task. See [import tests](https://github.com/JuliusBrussee/cavemem/blob/cd470f2386b10bbc8d6fafd7a94832593d5e036e/apps/cli/test/import.test.ts), [hook tests](https://github.com/JuliusBrussee/cavemem/blob/cd470f2386b10bbc8d6fafd7a94832593d5e036e/packages/hooks/test/runner.test.ts), and [search tests](https://github.com/JuliusBrussee/cavemem/blob/cd470f2386b10bbc8d6fafd7a94832593d5e036e/packages/core/test/memory-store-search.test.ts).

The upstream compression benchmark measures four small text fixtures using a local heuristic that takes the greater of a word count and rounded characters divided by four. It does not measure provider token usage, retrieval usefulness, or billed tokens. The pinned commit revises its advertised reduction floor; neither that floor nor a byte reduction should be reused as an Iron savings claim. See [benchmark](https://github.com/JuliusBrussee/cavemem/blob/cd470f2386b10bbc8d6fafd7a94832593d5e036e/evals/src/bench.ts) and [estimator](https://github.com/JuliusBrussee/cavemem/blob/cd470f2386b10bbc8d6fafd7a94832593d5e036e/packages/compress/src/count.ts).

Iron's independent fixtures in `eval/` instead measure expected-source coverage within actual byte budgets, process latency, and a labelled full-file baseline. They contain no historical source bodies. Answer correctness, current authority, peak RSS, and real model-token savings require separate evidence. The 40 historical queries were fixed before consulting any Iron search output; the ten fictional edge cases remain a separate diagnostic suite.
